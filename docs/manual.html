1. 这是什么

FK-Astro 是一个 PixInsight 处理模块,用神经网络对天文图像做去卷积:

  • 星点变得更紧实,顺便修正光学系统带来的轻微像差;
  • 非星点结构(星系、星云)的细节变得更清晰。

全部计算在你的本机完成,不联网,不上传任何图像。

它采用 BlurXTerminator(下称 BXT)的同类模型与参数体系:同一组滑块、 同样的数值范围、同样的语义,方便从 BXT 迁移过来或者对照使用。 本模块由 fk-astro 项目独立实现,与 RC Astro 无隶属关系。

2. 能解决什么问题

适合用的场景

症状典型原因
星点发胖、边缘发散光学系统像差、轻微失焦
星点"糊成一团"采样不足(undersampling)
星系旋臂、星云细节发软大气视宁 + 叠加后残留的 PSF
传统反卷积调不出好结果需要手工给 PSF、要防振铃、参数互相牵制

它替代掉的是什么

传统的 Richardson-Lucy 类反卷积要你:

  1. 手工估计或测量 PSF(形状、FWHM、是否随视场变化);
  2. 迭代次数、正则化强度、振铃抑制——三四个参数互相牵制;
  3. 一旦参数过头,就会出现黑边、振铃圈、"塑料感"。

这个模块把这些压缩成两三个强度值。神经网络自己判断哪里该锐化、 锐化到什么程度、哪里该收手。

它不能做什么

  • 不降噪。噪声水平基本保持不变,但锐化会让噪声看起来更明显。
  • 不去星。要分离星点请用 StarXTerminator 一类的工具。
  • 不修复拖线。跟踪误差造成的拖尾它处理不了。
  • 不做色彩校正、背景提取。请先用 DBE / SPCC。

3. 运行要求

系统

项目要求
操作系统Windows x64 —— 仅此一种,不支持 macOS / Linux
PixInsight1.9 或更新
内存建议 ≥16 GB。处理时另需约 每百万像素 24 MB 的累加缓冲(三通道双精度);6000 万像素级图像建议 32 GB
显卡不需要。有 NVIDIA GPU 可以加速

模型文件(唯一的外部依赖)

本模块不自带模型。 你需要准备一个 ONNX 模型文件:

bxt5.onnx        约 185 MB

这是本模块在 Windows 下唯一的外部依赖。

推荐放在:

C:\Users\<你的用户名>\Documents\FKAstro\bxt5.onnx

位置可以任意,只要在模块的 Model path 里指到它就行。建议固定放在上面这个目录, 方便以后复用。

模型文件不随发行包提供,请自备。

关于 onnxruntime

本模块的推理引擎是 ONNX Runtime,PixInsight 1.9 已经自带(版本 1.25 或更新),你不需要另外安装。模块运行时直接从 PixInsight 的 bin\ 目录加载它。

也就是说 —— 除了 PixInsight 本身,你只需要额外准备上面那一个模型文件。

4. 安装

装一个 PixInsight 模块要做三件事,缺任何一件菜单里都不会出现:

  1. 签名 —— PixInsight 强制要求模块签名,未签名的模块无法加载
  2. 拷贝 —— 把 .dll 与 .xsgn 放进 bin\
  3. 登记 —— 把模块写进 PixInsight 的模块清单。PI 1.9 不再自动扫描 bin\,漏了这步会「文件明明在、菜单里却没有」

4.1 用安装脚本(推荐)

先把 PixInsight 完全退出。签名期间 PI 不能处于运行状态 —— 否则新启动的进程只会把签名请求转交给已运行的实例并立刻返回,脚本无法判断签名何时完成。

cd <解压目录>\src\deploy
.\install-to-pi.ps1 -DllPath .\FKAstro-pxm.dll `
                    -XsskPath C:\path\to\你的密钥.xssk `
                    -XsskPassword "你的密码" `
                    -Sign -Install -Register
参数说明
-DllPath必填,要安装的 DLL
-XsskPath / -XsskPassword签名密钥与密码,配合 -Sign 使用
-PixInsightRootPixInsight 安装目录,默认 D:\PixInsight
-Sign执行签名
-Install把 DLL 与 .xsgn 拷进 bin\
-Register登记到 PixInsight 模块清单(PI 1.9 必需)。会先备份设置文件
-Force目标已存在同名文件时也覆盖(默认会拒绝)

脚本依次完成:体检 → 签名 → 拷贝 → 登记。全部成功后启动 PixInsight 即可。

4.2 手动安装

第一步:生成签名密钥(只需一次)

菜单 Script → Development → SigningKeys,在弹出的窗口里:

项目怎么填
Generate Signing Keys☑ 勾选
Developer留空。这一项是给认证开发者(CPD)用的
Local signing identity☑ 勾选(关键)
Export Signing Keys☐ 不要勾
Output → Keys file密钥文件路径,必须以 .xssk 结尾,例如 C:\PI\me.xssk
Output → Password设一个保护密码。记牢,后面签名还要用
Run点一下生成

第二步:把密钥注册给 PixInsight

菜单 Edit → Local Signing Identity...:

字段填什么
Keys file第一步生成的 .xssk 完整路径
Password第一步设的保护密码
Make the local signing identity persistent☑ 必须勾
Remove the local signing identity☐ 不要勾

⚠️ 这一步只能「选择」已有的 .xssk,不能新建。所以顺序不能反 —— 必须先做第一步。

⚠️ 不勾「persistent」的话,签名身份只在当前这次运行里存在,模块加载时会报 Unknown code signing identity —— 这是 PixInsight 1.9 上最常见的坑。

第三步:签名

D:\PixInsight\bin\PixInsight.exe ^
  --sign-module-file=C:\path\to\FKAstro-pxm.dll ^
  --xssk-file=C:\path\to\你的密钥.xssk ^
  --xssk-password="你的密码"

成功后会在 DLL 旁边生成同名的 .xsgn 文件。

签名是设备相关的 —— 签名身份由你的 PixInsight 许可证派生,所以每台机器都要就地重签,不能把别的机器上的 .xsgn 拷过来。

第四步:拷贝

把 FKAstro-pxm.dll 和 FKAstro-pxm.xsgn 两个文件一起放进:

<你的 PixInsight 安装目录>\bin\

第五步:登记到模块清单

PixInsight 1.9 不会自动发现 bin\ 里的新 DLL,必须把它写进设置文件:

%APPDATA%\Pleiades\core-001-pxi.settings

这个文件里有两个 <i k="Modules"> 节点(另一个是文件对话框的历史目录),要挑包含大量 -pxm.dll 条目的那个。在它的 </i> 之前插入一行:

<v k="00000059" t="s">@pxi_bin_dir/FKAstro-pxm.dll</v>

编号取清单里当前最大编号 +1。改之前务必备份这个文件,改坏了就还原。

更省事也更安全的做法:直接跑 install-to-pi.ps1 -Register,它会挑对节点、自动编号、备份并校验 XML。

第六步:重启 PixInsight

4.3 确认装好了

菜单 Process → Preprocessing 里应该出现 FKAstroInference。

没出现的话,按这个表查:

现象原因处理
菜单里没有 FKAstroInference,启动也不报错没有登记到模块清单跑 install-to-pi.ps1 -Register,或在 PI 启动时控制台看「Installing N module(s)」里有没有它
启动时提示 Unknown code signing identity签名身份没设成持久化重做第二步,勾上 persistent,再签一次
启动时提示模块签名无效签名之后 DLL 又被改过重新签名(签名针对的是文件字节,换一个字节就失效)
控制台报找不到模块文件清单里有、bin\ 里没有把两个文件拷进 bin\,或把清单那行删掉

4.4 卸载

两件事都要做:

  1. 删掉 PixInsight\bin\ 下的 FKAstro-pxm.dll 与 FKAstro-pxm.xsgn
  2. 从设置文件的 <i k="Modules"> 清单里删掉 @pxi_bin_dir/FKAstro-pxm.dll 那一行

然后重启 PixInsight。只删文件、不删清单的话,PI 启动时会去加载一个不存在的模块并在控制台报错。

5. 使用

5.1 界面总览

入口:Process → Preprocessing → FKAstroInference

参数分五个区:

分区包含的控件
ModelModel path
Stellar AdjustmentsSharpen stars、Adjust star halos
Nonstellar AdjustmentsSharpen nonstellar、Automatic PSF、PSF diameter (px)
OptionsCorrect only、Normalization
Additional OptionsTile overlap、Reflect border padding、Compute device、Verbose console output

用法和 PI 里其他进程一样:拖到图像上,或选中图像后点 Apply(F5)。

5.2 参数详解

Model — 模型

Model path 模型文件路径。点右边的 ... 选择你放好的 bxt5.onnx。 这一项必须设置,否则无法运行。

Stellar Adjustments — 星点

Sharpen stars — 星点锐化强度 0 ~ 0.7,默认 0.5

最常调的一项。数值越大,星点收得越紧。

取值什么时候用
0.3 ~ 0.4星点本来就不错,只轻微收紧
0.5通用起点
0.6 ~ 0.7采样不足、星点明显发胖

如果星点周围出现亮环或暗环,说明过头了,降 0.1 再试。

Adjust star halos — 星点光晕 -0.5 ~ 0.5,默认 0

正数加亮星点外圈,负数压暗。用于:

  • 星点外围有"光晕/雾"——用负值压下去;
  • 想给亮星一点柔和光辉——用正值。

绝大多数情况下保持 0。

Nonstellar Adjustments — 非星点

Sharpen nonstellar — 非星点锐化强度 0 ~ 1.0,默认 0.5

作用于星系、星云、尘埃带等非星点结构。这个值比星点那项敏感:

取值什么时候用
0 ~ 0.3只想轻微提细节,或图像本身噪声较大
0.5通用起点
0.7 ~ 1.0高信噪比的深空目标

过头表现为:星系核心变成"塑料块"、暗部纹理变硬、噪点被放大成颗粒。

Automatic PSF — 自动估计 PSF 默认 开

让网络自己从图像里判断星点的实际大小。绝大多数情况保持开启。

PSF diameter (px) — 手动 PSF 直径 0 ~ 8,默认 0

只有关掉 Automatic PSF 时才生效。适用于:

  • 星点极度异常(严重失焦、拖线、非圆);
  • 你知道自己的实际 FWHM,想强制给它。

一般填你的星点 FWHM(像素)。

Options — 选项

Correct only — 仅做校正 默认 关

打开后,前四个强度参数全部失效,只做"恢复被光学系统破坏的部分", 不做额外锐化。

适用场景:你不确定要不要锐化,但想先把光学像差修掉。 这是最保守的用法,几乎不会翻车。第一次使用建议先试这个。

跑完看不出变化是正常的。 这个模式只修正星点的形状,改动量通常在万分之一量级,在屏幕拉伸下几乎不可见 —— 不是没生效。想看明显的锐化效果,请关掉它并把 Sharpen stars 调到 0.5 以上。

Normalization — 归一化方案 默认 FKv3

模块把图像换算成网络能接受的格式,再换算回来。 保持 FKv3 即可,这是当前的标准方案。

None 表示不做任何归一化,像素原样送进模型。只适用于归一化本身接近恒等的模型; 用在 bxt5 上会得到错误结果且不会报错。除非你明确知道自己在做什么,否则不要选。

Additional Options — 附加选项

Tile overlap — 分块重叠比例 0 ~ 0.5,默认 0.2

模块把大图切成 512×512 的块分别处理,重叠部分用余弦过渡融合。

  • 保持 0.2。这是标准值,接缝不可见。
  • 改成 0 会更快,但极端情况下接缝可能出现极细微的痕迹。
  • 不要超过 0.5。

Reflect border padding — 边界镜像填充 仅旧方案使用。当前默认方案固定使用零填充,这一项不起作用。保持默认。

Compute device — 计算设备 Auto / GPU / CPU,默认 Auto

  • Auto:能用 GPU 就用 GPU,否则用 CPU
  • GPU:优先 GPU;不可用时自动回落到 CPU,不会报错
  • CPU:只用 CPU

勾上 Verbose console output 后,控制台会打印实际生效的设备:

fk-astro: compute device: GPU via CUDAExecutionProvider
fk-astro: compute device: CPU

⚠️ 前提是 onnxruntime 本身支持 GPU。 PixInsight 自带的那份 onnxruntime.dll 是 CPU-only 构建 —— 里面没有任何 GPU 执行器。这种情况下三个选项结果完全一样,都会打印 CPU。

要用 GPU,需要另外准备一份带 GPU 执行器的 onnxruntime:

  1. 取一份与 PixInsight 所带版本主版本号一致、带 CUDA 或 DirectML 的 onnxruntime 发行包;
  2. 把 onnxruntime.dll、onnxruntime_providers_*.dll 以及 CUDA/cuDNN 运行库放进同一个目录;
  3. 设环境变量 BXT_ORT_DLL 指向那个 onnxruntime.dll,然后重启 PixInsight。

模块会优先读 BXT_ORT_DLL,所以不需要替换 PixInsight 自带的文件,也不会影响 PixInsight 本身。

Verbose console output — 控制台详细输出 默认 开

运行时会往 PI 的 Process Console 打印归一化参数、分块数、耗时。 排查问题时很有用,平时可以关掉。

6. 标准处理流程

关键前提:必须在线性数据上运行

去卷积在未拉伸的线性数据上才有意义。不要在已经 STF 拉伸、 做过曲线或 HistogramTransformation 的图像上运行。

建议的顺序

1. 校准 + 叠加(得到 master)
2. 裁剪
3. 背景提取        DBE / ABE
4. 色彩校准        SPCC
5. ★ 去卷积        ← 就是这一步
6. 降噪            NoiseXTerminator 等
7. 拉伸            曲线 / STF / 遮罩拉伸
8. 后续调整        饱和、对比、局部增强

注意第 5 步和第 6 步的顺序:先去卷积,后降噪。 反过来做的话,降噪会把星点边缘抹平,去卷积就失去意义了。

第一次用的建议

  1. 先跑 Correct only,看它把图变成什么样。这一步最安全,基本不会翻车。
  2. 觉得效果不够,再关掉 Correct only,用 Sharpen stars = 0.5、

Sharpen nonstellar = 0.5 再跑一次。

  1. 用 Blink 或对比视图,把原图和处理结果来回切着看。
  2. 保留原图。不要在同一张图上反复叠加运行——会累积过度锐化。

耗时参考

CPU 模式实测约 每百万像素 8 秒(16 逻辑核):

图像尺寸像素数实测耗时(CPU)
2600 × 29007.6 M约 60 秒
3000 × 30009 M约 75 秒
4900 × 320015.7 M约 2 分钟
6000 × 380023 M约 3 分钟

GPU 能快数倍,但默认情况下用不上 —— PixInsight 自带的 onnxruntime 是 CPU-only 构建。想启用 GPU 请按 §5.2 里 Compute device 的说明准备一份带 GPU 执行器的 onnxruntime。启用后控制台会打印 compute device: GPU via ...,能据此确认是否真的生效。

8. 常见问题

Q:菜单里找不到 FKAstroInference

最常见的原因是漏了「登记」这一步。 PixInsight 1.9 不再自动扫描 bin\ 里的新 DLL —— 文件放对了、签名也对了,但没写进 PI 的模块清单,菜单里就不会出现,而且启动时不报任何错。 跑一次 install-to-pi.ps1 -Register 即可,详见 §4。

  1. 确认 FKAstro-pxm.dll 和 FKAstro-pxm.xsgn 都在 PixInsight\bin\ 下;
  2. 确认签名成功(没有 .xsgn 就不会加载);
  3. 完全退出 PixInsight 再启动(不是关窗口);
  4. 看 PI 启动时的 Process Console 有没有报错。

Q:报错说找不到模型 / 无法加载模型

Model path 没设或路径不对。注意:

  • 必须是 .onnx 文件;
  • 路径里有中文或空格一般没问题,但建议放在简单路径下;
  • 文件大小应该约 185 MB,如果是几百字节说明文件损坏。

Q:运行到一半报错退出

多半是内存不足。处理方法:

  • 关闭其他程序;
  • 分块裁剪后分别处理;
  • 或者换 Compute device = CPU(GPU 显存不足时常表现为这种报错)。

Q:输出全黑 / 全白

检查输入是不是已经是拉伸过的图像。本模块只处理线性数据。 也检查一下图像位深——16 位整数图和 32 位浮点图都支持,但不要是已经归一化过的特殊格式。

Q:星点周围出现一圈亮环或暗环

Sharpen stars 过头了。降 0.1 再试。也可以配合 Adjust star halos 用负值压一下。

Q:星系核心变成一块"塑料"

Sharpen nonstellar 过头。降到 0.3 左右,或改用 Correct only。

Q:接缝能看到?

正常不会。如果出现:

  • 确认 Tile overlap 是 0.2;
  • 用 Verbose 看分块数是否合理;
  • 把结果反馈出来。

Q:比 BXT 慢

目前只做了单线程为主的实现,GPU 加速也还在完善。CPU 模式下参考 §6 的耗时表。

Q:签名时卡住 / 提示要关闭 PixInsight

签名必须在 PI 完全退出的状态下做。PI 已在运行时,再启动它只会把签名请求转交给已运行的实例并立即返回,于是签名变成异步的,脚本无从判断何时结束。关掉 PI 再跑一次即可。

Q:选了 GPU,但速度和 CPU 一样

先打开 Verbose console output 看控制台那行 compute device:。如果打印的是 CPU,说明当前 onnxruntime 里没有可用的 GPU 执行器 —— PixInsight 自带的那份就是 CPU-only 构建。按 §5.2 准备一份带 GPU 执行器的 onnxruntime,并用环境变量 BXT_ORT_DLL 指过去即可,不必替换 PixInsight 的文件。

Q:处理到一半报「unknown exception in pipeline」

这是早期版本的一个已知缺陷(工作线程里的异常没有被正确捕获),已在当前版本修复 —— 现在改成在主线程上串行执行。如果仍遇到,请把 Verbose console output 打开后控制台的完整输出反馈出来。

Q:能和 BXT 混用吗?

不建议在同一张图上两个都跑。要对比的话,用原图各跑一次再比。

9. 效果预期与局限

能做到什么

在正常曝光的深空数据上,典型效果是:

  • 星点 FWHM 收紧约 2~8%(取决于原始星点有多松散;实测单张 300 秒数据约 1.8%,深叠加数据约 8%)。不是越多越好,过度收紧会失去自然感;
  • 星系旋臂、行星状星云的边缘轮廓更明确;
  • 光学系统的轻微像差(球差、彗差)得到部分修正。

做不到什么

  • 不能创造不存在的信息。如果原始数据里没有那个细节,它变不出来。
  • 不能修复严重失焦或拖线。
  • 不会改善信噪比。锐化之后噪声通常看起来更明显。
  • 对单张短曝光效果有限。信噪比太低时,它更倾向于不动。

什么时候不要用

情况为什么
图像已经拉伸过去卷积的数学前提不成立,结果不可控
星点严重拖线网络假设星点是圆形对称的
目标是密集星场(如球状星团核心)容易过度处理,建议降低强度或只用 Correct only
月亮 / 行星不适用,这是深空模型
已经跑过一次且结果满意反复叠加会累积过度锐化

一个诚实的提醒

这类工具的共同风险是"看起来很锐"但实际是假的:把噪声当成细节放大、 把星点压出人造的光圈。判断标准很简单——和原图来回切换看, 如果你只能看出"更亮更硬"而看不出"更多结构",那就是过了。
